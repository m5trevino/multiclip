## ✅ Completed: Step 0 — Integrate Hybrid Clipboard Monitor

### Summary
Replaced `ClipmanParser` (static file reader for `~/.cache/xfce4/clipman/textsrc`) with `HybridClipboardMonitor` (live clipboard capture) in `multiclip.py`. This is the user's #1 priority and a prerequisite for all subsequent V3 steps.

The monitor implements the proven approach from `test_clipboard_monitor.py`:
- **pynput listener** detects Ctrl+C globally → waits 100ms → reads `pyperclip` → saves
- **Fallback poll** every 1s catches right-click/menu copies
- **Deduplication** — won't save the same text twice
- **JSON persistence** to `~/.cache/multiclip/clipboard_history.json`

### Key Design Decisions

1. **Drop-in compatibility**: `HybridClipboardMonitor` implements the exact same interface as `ClipmanParser`:
   - `filepath` attribute → mtime polling in `MainWindow._poll_clipman()` continues to work unchanged
   - `parse(max_entries)` → returns newest-first list of `MonitorEntry` objects
   - `get_recent(count)` → thin wrapper around `parse()`

2. **Separate module**: Placed in `shared/hybrid_clipboard_monitor.py` rather than inlining, keeping `multiclip.py` focused and enabling standalone testing.

3. **Daemon threads**: Both the pynput listener and the poll loop run as daemon threads. They do not prevent clean exit.

4. **Graceful shutdown**: `MultiClipV2.__init__` registers `clipboard_monitor.stop()` in the existing `atexit` and `signal.SIGINT`/`SIGTERM` handlers.
